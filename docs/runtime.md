# Runtime, validation and adaptation

`src/runtime/index.ts` exports `runModel(workflow_id, reset_epoch)`, `repairModel(workflow_id, reset_epoch)`, `validateRevisionModel(workflow_id, reset_epoch)` and `recoverModelRuns()`. The worker dispatches them outside persistence transactions. Scripted generation is owned by the workflow engine and is visibly separate from the OpenAI adapter.

The adapter uses the installed OpenAI 7.23.0 Responses API, model `gpt-6-astra`, reasoning `medium`, `store:false`, strict JSON schemas, no parallel tool calls and SDK `maxRetries:0`. It counts request input before generation, reserves cost durably before dispatch, and stores attempt status, request identity, measured usage and unresolved reservations in tenant/epoch/workflow-scoped receipts. Maximums are nine generation requests,16 tool executions,24,000 input tokens per request,120,000 cumulative input tokens,24,000 cumulative output tokens,$3 per run and a300-second absolute deadline. Every server hydration/tool/commit checks the pinned lease, epoch and context. Network uncertainty retains the full reservation and blocks reset. Automatic repairs inherit the same budget and deadline. An explicitly applied human document edit or verified fact correction may start a linked child run only after every current and archived reservation is settled. The immutable parent ledger, run/budget links, resolution identity and cumulative workflow costs/tokens/attempts remain retained; human waiting does not permanently expire the next authorized review. No provider error is replaced with a fixture draft.

Registered tools read pinned company facts, baseline clauses and explicit legal-text spans, and record unverified fact or protected harness proposals. Proposals cannot activate facts, alter thresholds, approve documents, send email, execute code or promote a configuration. Read outputs have explicit continuation offsets and cannot be silently truncated. Exact evidence citations must resolve to spans actually retrieved by that run.

Generated clause changes become immutable revisions. A separate model checker receives full relevant authoritative provision text, the complete candidate, baseline and facts. Counted context is divided into at most three batches; oversized mandatory context causes human escalation. The checker cannot approve the workflow. Deterministic validation checks content/source/raw-byte hashes, authoritative source identity, operative dates and freshness, all fact/provision IDs, quote spans, required disclosures, unchanged-clause preservation, missing facts and explicit unsupported claims. Scripted checks are rule checks; they are not independent model or human legal opinions.

`src/adaptation/index.ts` exports `evaluateHarness(epochOrOptions)`, `rollback(epochOrOptions)`, `validateHarnessPatch()` and `laterEventProof()`. The only patchable fields are two guarded, false-to-true prefetch flags. Arbitrary paths, parent paths, prototype keys, extra fields, repeated operations and omitted `test` operations are rejected. The campaign admits one candidate per diagnosis and at most three daily proposals. It freezes case data, source hashes, evidence maps, model settings, runtime/validator/evaluator code and the champion version plus generation. A final transaction checks all bindings and the reset epoch before promotion. Rollback increments the generation and preserves in-flight pins.

The local comparison executes11 frozen applicability fixtures plus regression and holdout mutations against the production validators, then replays both retrieval configurations against the same source workflow snapshot. It records measured missing-bundle repairs separately from the intentionally retained citation-repair challenge. A later distinct persisted workflow must read the promoted version and exhibit zero missing-bundle repairs; the proof includes an isolated baseline counterfactual. Local results explicitly report zero live model calls.

When `KIARA_MODEL_MODE=openai`, deterministic results alone cannot promote. `src/adaptation/campaign.ts` reserves an explicit separate$18 campaign budget and starts six alternating baseline/candidate trials as isolated child processes. Each has an isolated local store, the same frozen facts/base/sources, the foreground$3/300-second caps, disabled email, no approvals and no access to parent MongoDB. The parent retains Atlas/local campaign and trial receipts; at most72 total generation attempts and a900-second campaign deadline are permitted. Promotion requires all six actual semantic validations, consistent frozen bindings, the1→0 repair reduction in all three pairs, and no greater than25% mean latency or cost regression. Missing credentials, process loss, unknown cost, budget exhaustion or failed validation makes the result inconclusive/failed. Expired parent campaigns retain reservations for reconciliation through `recoverEvaluationCampaigns()`; reset is blocked while any campaign is running or financially unresolved.

## Verification performed

`node --import tsx --test tests/runtime.test.ts tests/adaptation.test.ts` exercises the frozen legal cases, validation mutations, SDK adapter with an injected test provider, timeout/crash accounting, protected patch rejection, actual persisted approval/promotion/later-event behavior, generation CAS, six-trial budget accounting and real child-process isolation without credentials. The independent reviewer added adversarial regressions in `tests/review.test.ts`.

No OpenAI or Atlas credentials were available during this implementation. No live model generation or live six-trial campaign has been claimed. The actual child-process test executes the missing-credential failure path with zero model requests. A configured campaign may legitimately fail the protected capacity, deadline or quality gates; the app must surface that outcome and keep the existing champion. Unknown provider charges require operator reconciliation from retained receipts before reset or further spending.

Official API references checked during implementation: [Responses function calling](https://developers.openai.com/api/docs/guides/function-calling), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra). Cost reservations use the frozen T06 pricing snapshot of$10/$50 per million input/output tokens; account entitlement and live billing were not verified.
