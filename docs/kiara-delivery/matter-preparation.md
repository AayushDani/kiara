# Preparation for accepted work plans

An accepted generated work plan now uses its objective and required tasks when preparing a matter artifact. `matter.prepare` on this path freezes the exact current matter/version/hash, accepted plan/hash, task list, scope, and rule version. It records an owned preparation review task and durable conversation run. It does not create a proposal or approve any work at admission.

The existing bounded conversation worker supplies the generation, independent item-by-item support check, pinned model configuration, shared spend ceiling, durable attempts, and uncertain-outcome recovery. No new paid path or automatic retry was added. The model receives the accepted plan as attributed intent, not as a confirmed statement of current practice. It must propose objective-specific text, missing inputs, and optional typed tasks; it has no tools or record mutation capability.

Before model dispatch, the packet is narrowed to the matter's exact audience, including recursive source/fact audiences. Previous conversation text is omitted. Private supplemental evidence available only to the requesting person is excluded from a team packet. Registered coverage with different audience/dependency scope is omitted with an explicit limitation and cannot establish legal qualification. The full recursive source/fact proof graph behind the frozen objective and task notes is retained and version-bound even when none of those records appears in the ranked excerpts. Current scope and coverage are rechecked before every provider step and attachment. Existing Atlas hydration still applies before this narrower packet is constructed; vector rank is unchanged.

The resulting `DraftProposal` has `request.kind = matter_packet` and an explicit frozen `request.matter` basis. The owner must inspect and accept or reject its complete text through the existing exact draft decision. Acceptance creates one current `Proposal` in `legal_review`, preserves unresolved original factual predicates, adds proposed tasks as pending, resets business/legal review, and invalidates prior decisions on a replaced proposal. It grants no facts, legal applicability, publication, signature or execution authority. Outstanding submitted effects prevent replacement preparation until reconciliation.

Changing the objective, tasks, plan, policy, source, current document head, or terminal matter state makes pending work stale. A canceled matter cannot receive late generated preparation. Idempotent adoption survives restart without a duplicate proposal. Local mode reports that accepted-plan semantic preparation requires the configured model; it never substitutes the previous fixed data-flow/notice paragraph.

The pre-existing bounded checklist path for matters without an explicitly accepted generated plan remains a separate limitation. It is not represented as this new semantic preparer. The new finite tests use supplier onboarding, unrelated private material, missing procurement-owner facts, exact adoption/replay, stale intent, cancellation, and local-mode unavailability. Provider responses and support checks are injected; no live quality or legal qualification is claimed.

Substantive work now has an explicit task purpose. Proposal business/legal decisions complete only `proposal_review` gates. Generated negotiation, analysis, and other business/legal work remain `work` tasks; exact artifact acceptance completes only the separate `artifact_review` task. Legacy compatibility recognizes the previous service-generated gate titles only when there is no generated predicate field. It does not convert arbitrary legal/business tasks into approval gates.

A current effective assigned owner can record `matter.task_complete` with the matching business/legal capacity, exact matter version, current same-audience retained source IDs, and a named human attestation. The command must carry one-to-one inspected source-version, content-hash, and dependency-hash maps; a source or nested proof changed after inspection is rejected. The completion pins the full recursive source/fact fingerprint and contributes source lineage to the matter. Changed completion evidence invalidates prior proposal review so the refreshed packet includes it. Revoked evidence hides its derived note, and pending substantive work prevents closure even when proposal approvals exist. Stale completed work can be re-attested by the currently routed qualified owner; prior immutable attestation events remain. Legacy generated business/legal tasks marked done without a valid attestation fail closed and have the same recovery path. This is attributed human completion evidence, not provider readback or proof that a legal conclusion is correct.

Main workspace projections also require the parent conversation/matter to remain visible before returning child messages, conversation-only facts, scenarios, draft proposals, review proposals, approvals, actions, counsel, learning, effort records, or matter events. Exact counsel packet grants remain usable because the explicitly granted matter and selected children satisfy these filters.

Focused qualification: 18 preparation and independent review cases pass, including empty ranked basis preservation, audience narrowing, private counsel packet access, unlinked inspected-source mutation, nested source-free fact changes, delegated re-attestation, and legacy unevidenced completion. No live provider request was made.
