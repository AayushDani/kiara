# Concurrent original purge claim · 27 September 2026

## Reproduced race and repair

Before the repair, a controlled local test paused the first retention worker after its purge claim. A second worker entered the physical original adapter, producing **two** calls for the same retained bytes. The test failed at `2 !== 1`.

The worker now stores an opaque claim ID and 15-minute expiry with the purge status in the workspace transaction. Another worker holds while that claim is live; a different due deletion job sharing the original also holds. After expiry, a new worker may retry; an old worker's late failure cannot overwrite the new claim's completion. This is a bounded lease and requires an idempotent physical adapter if a request outlives its lease.
