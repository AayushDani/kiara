# Shared provider ledger anchor · 28 September 2026

Independent release review found that a hosted process could point `KIARA_BUDGET_DB` at an empty Mongo database and create a fresh `provider_spend_authorization` row. That would reset Kiara's application cap while the previously used shared ledger still held prior charges. It also found that settlement of an absent charge returned success, so a target drift after provider response could make an answer appear accounted without recording its cost.

The guarded admission now requires a retained settled-charge identity bound to the Mongo host set, explicit database, minimum request count and conservatively budgeted spend. Changing either floor invalidates the anchor. Hosted Vercel, worker, production, OIDC and Temporal signals enforce the guard before any new reservation, even if v2 storage mode is mis-set. Status fails closed instead of reporting zero on an unverified hosted ledger. Settlement of a missing charge fails; settlement and recovery on a hosted process require the same anchor. The v2 conversation path skips settlement if admission was denied before a reservation. These changes were exercised by focused offline regressions; they do not by themselves prove the hosted environment uses the same target.

A read-only operator command against the previously inspected Atlas cluster with `MONGODB_DB=kiara_v2` and `KIARA_BUDGET_DB=kiara` returned an anchor of `092eb87491a008b49f8f36a4ebe98a0c38238a291fd4af8d5e9d2b7510647bc8`, minimum **579** requests and minimum **24,342,835 micro-USD** ($24.342835) of conservatively budgeted spend. A second read-only check with those exact three values returned `ledgerAnchorVerified: true`. No charge ID, credential, source content, provider call or Mongo write was printed or made. The values are a baseline for this inspected ledger; a reviewed transfer requires new values and account reconciliation.

`npm run check` passed. The focused spend, release-readiness and v2 AI run passed **40/40**. [GitHub CI run 36374234126](https://github.com/AayushDani/kiara/actions/runs/36374234126) passed type generation, TypeScript, the full test suite and production build for `9002db8`. Independent read-only re-review found the three reported anchor, floor-drift and missing-settlement paths closed at that commit; it did not repeat tests because the review worktree had no installed `tsx`. The later release branch also has a separate legacy-API-disabled readiness gate; integration must preserve that gate. Hosted Vercel and Render variables, direct paid admission on the deployed commit, cross-host equality, provider invoice comparison and any production ledger transfer remain connected qualification work.
