# Protected forwarding intake

The receiving adapter is opt-in per private owner and exact receiving alias. It verifies a Resend `email.received` webhook over raw bytes, records one durable provider-message reference, then a local or managed worker fetches the message from the configured receiving account. The webhook body is not treated as source content. Replays do not create another source, original or workflow.

The receiving registry is `KIARA_V2_EMAIL_INSTALLATIONS` or a bounded mode-0600 file named by `KIARA_V2_EMAIL_INSTALLATIONS_FILE`. Each entry supplies a unique `id`, `tenantId`, provisioned integration `actorId`, member `ownerId`, operator account label `accountId`, explicit `accountScope: exclusive_owner` attestation, `enabled`, future `validUntil`, exact lowercase `receivingAddress`, `allowedSenders`, credential variable names `tokenEnv` and `webhookSecretEnv`, exact `rawDownloadHosts`, and private `scope` with exactly the owner and integration actor. Shared-account routing is unsupported: duplicate aliases, account labels, API-key references/values and webhook-secret references/values are rejected. The operator must dedicate the provider account to this private owner and bind both credentials to it; an account label is not a provider attestation. Tenant routing rests on that protected account binding, the signed event and authenticated provider read. `to` and `received_for` are only extra consistency checks: a populated `received_for` mismatch fails before original download. Neither field establishes an authenticated SMTP envelope or cross-tenant routing permission. This adapter does not change DNS, create a mailbox or certify account connectivity.

A source is automatically admitted only when its outer sender matches the explicit list, the provider's receiving authentication reports DMARC pass plus SPF or DKIM pass, and a nonempty plain-text body is present. Everything else remains private quarantine. These transport checks do not certify the people named inside a forward, quoted headers or contractual statements. Even admitted email has unknown authority and cannot confirm facts, approve, sign, publish or start an action. Quarantined/rejected sources are excluded from ordinary retrieval, vector eligibility, fact confirmation and current-evidence decisions. The exact mapped owner may accept or reject a quarantine after reviewing its frozen source version, source hash and receipt hash; another administrator cannot impersonate that owner.

The full raw `.eml` is retained through tracked encrypted-original intake before source attachment. That original contains the provider-supplied message and attachments. Attachment metadata is explicit; attachment text is not parsed or represented as known content. HTML is not rendered or used as fallback model text. Plain text is bounded at 80,000 characters, structured source evidence at 100,000 characters, API reads at 2 MB and raw originals at 10 MB. Unsupported/large messages fail visibly rather than being silently truncated.

Raw-original downloads require an unexpired HTTPS URL on an exact configured host. They carry no API credential, reject redirects, resolve only public addresses, and pin the selected address to the TLS request with pooling disabled. API access is fixed to `api.resend.com`. Receiving configuration, credential continuity, owner/integration membership versions and worker lease are rechecked before attachment. Revocation immediately removes source eligibility. Deletion propagates into derived content and tracks original cleanup; replay never restores deleted source payload. Application erasure does not claim deletion from the upstream mailbox or provider backups.

Server exports are `acceptEmailWebhook`, `processEmailIntake`, `emailIntakeView`, `emailIntakeSummaries`, and `reviewEmailIntake` in `src/v2/integrations/email.ts`. Review accepts only `expectedSourceVersion`, `expectedSourceHash`, `expectedReceiptHash`, and `decision: accept|reject`. Root routes supply authenticated actor/session/CSRF controls. The `email_intake` outbox and workflow carry tenant/intake/outbox references only. Queued reads retry under a lease; terminal quarantine awaits the owner. Blocked configuration/format cases require explicit operator review rather than automatic acceptance.

Official protocol references: [webhook verification](https://resend.com/docs/webhooks/verify-webhooks-requests), [metadata-only webhook and body retrieval](https://resend.com/docs/dashboard/receiving/get-email-content), [received message fields and original download](https://resend.com/docs/api-reference/emails/retrieve-received-email). The receiving API's `received_for` field derives from message `Received` headers and is not used as authenticated user identity. Authentication comes from the provider receiving result, not copied message headers. The installed Resend SDK's verifier is used; bounded reads use the documented fixed endpoint because its local response type does not yet include the optional authentication object.

## Local evidence

`tests/v2-email-intake.test.ts` covers signatures, aliases, replay/conflict, exact encrypted original, source-only admission, unknown sender quarantine, exact owner review, private retrieval exclusion, original-download scope, concurrent workers, membership/configuration changes, deletion and refs-only processing. The initial notification/integration/legal worker run passed34/34 (`evidence/email-notification-workers-tests.log`). After the dedicated-account and owner-discovery checks, the final email/notification/independent worker run passed36/36 in4.95seconds (`evidence/email-notification-independent-review.log`), and TypeScript exited0. The four independent notification cases include unexpected HTML/attachments, changed recipient, unknown deduplication and late acknowledgment after opt-out. All provider responses were injected, including raw originals; no live mailbox read or email send occurred. Actual installed Temporal SDK bundling succeeds for all eleven workflows (`evidence/temporal-email-notification-bundle.log`); this is not a managed-server workflow/replay qualification.
