# Hybrid retrieval and normalized persistence

Source coverage: product plan v2 §§7–8 and §13 (authorized retrieval, legal source inventory, canonical persistence), §§14–16 (bounded provider cost, migration, restart and retention). These adapters are implemented and tested with injected providers and deterministic storage images. Independent qualification also exercised MongoDB Community 8.0.32 on an isolated local replica set: actual aggregate/normalized transactions, interrupted migration resume, ownership races, permanent index fences, historical redaction and restart. The current local suite passed 11 tests; [the normalization target record](evidence/normalization-plan-target-sep28.md) covers the two-database regression. No customer Atlas search or paid embedding request was exercised by this local suite. Managed failover, cloud index lag and production capacity remain unqualified.

## Retrieval

The default `KIARA_V2_RETRIEVAL_MODE=local` remains exact/keyword retrieval. `atlas` requires a Mongo connection (`KIARA_V2_ATLAS_URI`, falling back to `MONGODB_URI`) and both `KIARA_V2_ATLAS_SEARCH_INDEX` and `KIARA_V2_ATLAS_VECTOR_INDEX`. Missing configuration, unavailable query indexes or incomplete authoritative revisions stop this mode; it never silently substitutes local retrieval.

`hybridIndexDefinitions(hybridConfig())` returns operator index definitions for the `v2_search_chunks` collection. `syncHybridIndex(actor,recordIds)` is an explicit admin action on 1–20 currently authorized records, bounded to 200 chunks. It does not grant an administrator access to private records. Documents, observations and confirmed reusable facts are chunked with current record fingerprints. Controlled document heads are selected before ACL filtering; historical document sources do not reappear as independent source snippets.

Before querying, the service derives an allowlist of immutable chunk IDs from current tenant, entity, membership, source grants, fact validity and recursive lineage. Both full-text and vector search contain these prefilters and return IDs only. Exact, full-text and vector ranks are merged with literal reciprocal rank fusion `sum(1/(60+rank))`, with ranks starting at one. Text comes from authoritative records after a second current access check, never from search output. The parent conversation lease is checked before embedding dispatch and search. The existing answer and support-check stages recheck access again before dispatch and attachment. Revocation is effective before eventual search-index cleanup.

This is real configured Atlas keyword/vector query code; there is no learned reranker. Search has a 10,000-authorized-chunk admission bound. Index synchronization is disabled by default. An explicit operator standing policy can admit automatic scoped maintenance after accepted record changes; see index-inventory.md. Manual admin sync remains available. Index physical deletion is replayable through `purgeHybridRecords`; deletion of Atlas-managed snapshots or provider backups is not verified by that hook.

## Embedding accounting

`text-embedding-3-small`, 1536 dimensions and `cl100k_base` are pinned. `js-tiktoken` produces the exact token array submitted to the API; there is no character-ratio estimate. Standard input pricing is fixed at $0.02 per million tokens. Requests share the existing operator-wide spend ledger and configured ceiling; no cap is increased. Every query is owned by the accepted conversation run, and each index request is owned by actor and immutable chunk identity. Durable prepared/dispatched/completed/unknown records, bounded leases and recovery markers precede ledger I/O. Unknown outcomes cannot resubmit. Known results require exact token usage, model identity and vector dimensions. Raw input text is not duplicated in embedding receipts.

## Normalized store

`KIARA_V2_STORE_MODE=normalized` requires a Mongo replica set or Atlas. Per-kind collections `v2_records_<kind>` hold individual records, memberships, outbox entries and command/provider receipts; `v2_normalized_heads` holds current metadata, ordering manifest, generation, version and checksum. Snapshot transactions read a consistent head and record set. Writes update only changed rows and atomically compare the head version, generation and hash with majority write concern. No provider call occurs inside a transaction. The per-tenant aggregate BSON ceiling is removed; each individual record remains bounded below Mongo's document ceiling.

The service currently hydrates the full tenant state to preserve existing command invariants. Thus normalized persistence avoids whole-aggregate writes and BSON limits but does not yet establish unbounded tenant read scalability or paginated workspace APIs. These are explicit remaining scale limits.

`normalizedMigrationPlan` is an inert checksum-bound image plan. The operator's `normalize-check TENANT INSPECTED_AGGREGATE_HASH` prints a reviewed plan hash bound to the exact MongoDB URI/database fingerprint, tenant, state version/hash and aggregate owner fence. Apply requires `normalize TENANT INSPECTED_AGGREGATE_HASH REVIEWED_PLAN_HASH`. The operator rechecks that binding before staging and again before cutover. Cutover stages an immutable generation in bounded batches within a snapshot transaction and retains an exact backup. The final snapshot transaction verifies staged integrity and unchanged aggregate version/hash, fences aggregate writers and publishes the normalized head. Aggregate CAS includes the absence of that fence. Empty normalized tenants also insert a fenced sentinel under the same aggregate tenant key, so mixed-mode bootstraps contend on one ownership document. Existing workers and API instances must be configured for normalized mode at cutover; stale aggregate instances fail closed.

`normalize-rollback-check TENANT INSPECTED_NORMALIZED_HASH` prints a second plan hash bound to the current normalized head, frozen aggregate owner fence and exact MongoDB target. `normalize-rollback TENANT INSPECTED_NORMALIZED_HASH REVIEWED_PLAN_HASH` requires that plan before any write. Rollback copies the **current** normalized state, including accepted command receipts, tombstones, role revocations and unresolved effects. It never restores the old pre-migration state. It refuses a state exceeding the aggregate capacity. Staged and historical generations are retained until explicit retention cleanup. `purgeNormalizedHistory` applies the shared deletion policy to inactive record generations, retained migration backups and the frozen aggregate fence. Canonical ownership writes serialize cleanup with late staging and cutover; changed archives become unavailable for migration replay. Host-managed database backups still require operator verification. No migration path dispatches external actions. The two-database local replica regression verifies that a reviewed plan cannot be applied to an otherwise identical cloned tenant in a different database. Managed failover, backup restoration and Atlas index-lag drills remain required.

Index erasure uses a permanent per-record tombstone in the index database. Every upsert and purge writes that same fence in a Mongo transaction; a writer paused before deletion cannot insert after purge completion. Sync also retains a durable attempt receipt and removes its chunk if the post-write authority check fails. Query-time authorization remains independent of this physical cleanup protocol. The permanent-fence race was independently exercised against the local Mongo replica, including a writer paused after its snapshot read.

Embedding admission can be retried only when the previous immutable attempt never reached provider dispatch. Each retry gets a new charge identity and keeps admission history. Every subsequent transition compares that identity; an expired prior process cannot dispatch or settle a successor. Known provider rejection and unknown dispatch outcomes remain non-retryable under the original owner. The shared ledger retires recovered reservation IDs, preventing a delayed reservation write from reviving a canceled attempt.
