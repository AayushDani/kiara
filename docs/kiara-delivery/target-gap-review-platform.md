## Review repairs confirmed in other owners' code

- Original intake now fences a source-deletion hash before object I/O and fences another same-hash orphan purge in the claim transaction. The reverse order is protected because purge checks other staging or unexpired retained intakes. New reviewed intake may follow a completed orphan purge; a source-deletion fence remains permanent.
- Interrupted intake recovery reads the exact manifest, verifies tenant/hash/byte count and compares the current receipt to the original snapshot before recording its reference. It cannot replace an established reference or revive a purging/purged intake.
- Source retention treats null-reference staging writes as explicit pending exceptions. Encrypted local purge checks exact tenant/content/key identity and missing-file readback; S3 purge deletes only the pinned version and never bypasses retention controls. Managed provider behavior remains unqualified.
- Global spend recovery retires a missing pre-dispatch identity with a zero settled tombstone. Missing dispatched identity remains blocking unknown even with zero recorded reservation; conservative coverage requires an explicit reconciliation record. A later reservation cannot revive the old identity.
- Retention/artifact/index workflow wrappers accept only exact opaque tenant/outbox/aggregate references, validate canonical ownership and report bounded scheduling state. They do not carry retained source text in Temporal history.
